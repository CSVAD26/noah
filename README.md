
# Project 1 

I am always looking for ways of incorporating analog, claymation visuals to a programmed, digital interface. For the drawing tool project, I knew I wanted to allow users to draw with a textured brush and a darken blend mode that would create painterly strokes. Finally I arrived at the concept of emulating the "roguelike deck-builder" gameplay loop through limited equipment choices and random chance. The user is presented with three cards, and a dice roll. Each card is either a random color, or random clay texture. Each card has a randomized brush size as well. No text instructions are given, and there are no keybinds. The css hover animations and cursor pointer give user feedback that they can select these ui elements with the mouse. I find this minimal approach to UI, with less instruction and more visually striking glyphs, to be great for user exploration. Their artistic choices could be inspired by the visual design and textures rather than a set of rules or features they have to learn first. By keeping it limited, the user is quickly able to explore and master all aspects of the system, leaving more time for the artistic process. Programming this tool was not super difficult, and only came by a few snags while trying to get the multi-layered, instancing setup figured out. I knew I wanted to keep the programming complexity minimal so I would be able to produce a good foundational prototype without relying on AI assistance. Luckily I have recently done some website development, so I had some helpful javascript functions I could bring in here to speed up the coding process, such as a requestAnimationFrame based bezier curve function for animating, and sprite animation triggers. I knew I wanted the UI to be involved on the screen instead of a sort of task-bar and canvas layout, as the turn system enabling and disabling creates a dynamic engagement loop. Quickly switching between actively drawing, and then choosing the material for the next drawing turn, lets the user continually reflect on their art and strategize how they want to move forward with their color choices. One thing I really wanted to add but didn’t find the time to implement correctly was texture mirroring. By randomly rotating a texture, and mirroring the scale on the x and y axis we create a tileable texture that can be repeated seamlessly. This would have really diversified the amount of brushes available. To adjust for this loss of diversity, I added a simple stroke color, which is very simple but effective for color blending or background filling. Something that came up during testing was an unintended over-analysis of the card suit. Each card has a randomized suit (hearts, clubs, spades, diamonds), but it was purely for visuals, and was not meant to indicate any kind of functionality. This is a drawback to my minimal, art driven design as it may lead users more astray than if there were direct instructions. It is damaging for this project specifically, since users might choose textures based on an idea of what suit is best in that context, rather than what texture they actually want to draw with. Overall I am happy with the project, and it achieves my goal of implementing a roguelike deck-builder style gameplay loop to a drawing program.
